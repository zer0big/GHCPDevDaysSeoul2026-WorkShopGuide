# 레슨 5 - 편집 전에 계획하기

레슨 4에서 준비한 **두 번째 세션(워크트리)** 에서 진행합니다. 바로 구현하지 않고, 해결 방법을 먼저 계획하고 검토한 뒤 구현을 승인합니다.

**이 레슨에서 할 일**

- `/plan`으로 구현 계획을 요청합니다.
- 제안된 계획을 검토하고 보완합니다.
- 계획을 승인한 뒤 구현합니다.

---

## 5-1. 계획 요청

1. 두 번째 세션으로 이동합니다.
2. 입력창에 남아 있는 `#2` 등을 지우고, 아래 요청 전체를 입력한 뒤 Enter를 누릅니다. (이슈 번호가 다르면 바꿉니다.)

```text
/plan GitHub 이슈 #2의 본문과 인수 조건을 읽고 구현 계획을 세워 주세요. 기존 퀴즈를 조사하고, 문항 순서를 섞는 방법과 변경할 파일, 테스트 방법을 제안해 주세요. 정답 연결, 진행률, 점수 계산, 접근성, 단일 HTML 파일 및 외부 의존성 없음 조건이 유지되는지 검토해 주세요. 아직 코드를 수정하지 말고 계획만 제시한 뒤 기다려 주세요.
```

3. 화면 하단에 **Plan** 모드가 표시되는지 확인합니다. 계획 검토 창이 열려 있으면 하단 표시 대신 **Plan Ready for Review** 메시지를 확인합니다.
4. 이슈를 다시 고르라는 질문이 나오면 **퀴즈 문항 순서를 실행마다 섞기**를 선택합니다.

> Plan 모드는 `Shift+Tab`으로도 전환할 수 있습니다.

## 5-2. 계획 검토

다음 내용이 계획에 들어 있는지 확인합니다.

- [ ] 시작·다시 시작할 때 기존 10문항의 순서를 섞는다.
- [ ] 문항이 빠지거나 중복되지 않고, 정답 연결이 유지된다.
- [ ] 진행률, 점수 계산, 접근성 등 기존 동작이 유지된다.
- [ ] 변경 파일은 `index.html` 하나다.

빠진 내용이 있으면 추가를 요청합니다.

## 5-3. 구현 승인

계획이 마음에 들면 **1번**을 선택하고 Enter를 눌러 구현을 시작합니다. 선택 메뉴가 없으면 다음을 입력합니다.

```text
검토한 계획대로 이슈 #2만 구현해 주세요. 아직 커밋하거나 푸시하지 마세요.
```

> **계획 모드가 유용한 경우**: 요구 사항이 모호하거나 변경 범위가 넓을 때입니다. 코드 수정 전에 접근 방식을 맞추면 불필요한 수정과 재작업이 줄어듭니다.
