# 레슨 4 - 이슈를 병렬로 작업하기

터미널에서 GitHub 이슈를 만들고 구현합니다. 서로 독립적인 작업은 별도 세션과 워크트리(Worktree)에서 진행해 변경 사항이 섞이지 않게 합니다.

**이 레슨에서 할 일**

- 범위가 명확한 GitHub 이슈 3개를 만듭니다.
- 사이드 패널에서 이슈를 채팅에 추가하고 구현합니다.
- `/diff`로 변경 사항을 검토합니다.
- 격리된 워크트리에서 두 번째 세션을 준비합니다.

> 이 레슨의 명령은 별도 안내가 없으면 **Copilot CLI 입력창**에 입력합니다. 터미널에서 실행하는 명령은 "터미널에서"라고 표시합니다.

---

## 4-1. 백로그 만들기

모든 참가자가 같은 순서로 진행할 수 있도록 이슈 제목을 지정합니다.

```text
현재 우주 퀴즈를 검토하고, 아래 3개 개선 사항을 이 순서대로 각각 GitHub 이슈로 생성해 주세요. 각 이슈에는 사용자 관점의 설명과 완료 여부를 확인할 수 있는 인수 조건을 포함하고, 서로 독립적으로 진행할 수 있도록 범위를 한정해 주세요. 아직 구현하지 마세요.
1. 결과 화면에서 오답을 복습할 수 있게 하기
2. 퀴즈 문항 순서를 실행마다 섞기
3. 최고 점수를 브라우저에 저장해 결과 화면에 표시하기
```

생성 후 이슈 번호를 확인합니다.

```text
!gh issue list
```

새 저장소라면 보통 `#1`, `#2`, `#3` 입니다. 번호가 다르면 이후 레슨의 `#2`를 **"퀴즈 문항 순서를 실행마다 섞기" 이슈의 실제 번호**로 바꿔서 입력합니다.

> 사이드 패널의 Issues, Pull requests 탭이 비활성화되어 있으면 [TROUBLESHOOTING.md](../TROUBLESHOOTING.md#4-사이드-패널에-issues-pull-requests-탭이-비활성화됨)를 참고합니다.

## 4-2. 현재 세션에서 첫 번째 이슈 구현

1. 입력창이 **비어 있는 상태**에서 `←` 키를 눌러 사이드 패널을 엽니다.
2. `Tab`으로 **Issues** 탭으로 이동합니다.
3. `↑` `↓`로 **결과 화면에서 오답을 복습할 수 있게 하기**를 선택합니다.
4. 전체 내용을 먼저 보려면 `Enter`, 채팅에 첨부하려면 `c`를 누릅니다.
5. 입력창에 다음을 입력합니다.

```text
첨부한 이슈의 설명과 인수 조건에 맞게 구현해 주세요. 다른 이슈는 구현하지 말고, 아직 커밋하거나 푸시하지 마세요.
```

## 4-3. `/diff`로 변경 사항 검토

레슨 3의 첫 커밋을 기준으로 달라진 내용을 확인합니다.

```text
/diff
```

1. 변경 파일을 살펴보고 **요청한 이슈 외의 변경이 없는지** 확인합니다.
2. 문제가 있으면 수정을 요청한 뒤 다시 `/diff`로 확인합니다.
3. 브라우저에서 새 기능과 기존 퀴즈 동작을 확인합니다. (`!start index.html` 등)

Git 명령으로도 확인할 수 있습니다.

```text
!git status
!git diff
```

> 첫 번째 이슈의 변경은 이번 실습에서 **커밋하지 않고 그대로 둡니다.** 레슨 9 시작 시 임시 보관(`git stash`)합니다.

## 4-4. 두 번째 이슈를 위한 세션과 워크트리 준비

1. 사이드 패널의 **Sessions** 탭으로 이동합니다.
2. 화면 아래 안내에 따라 `n`을 눌러 새 세션을 만듭니다.
3. **새 세션의 입력창**에서 실행합니다.

```text
/worktree
```

4. 별도의 작업 폴더와 새 브랜치가 생성됐는지 확인합니다.
5. **Issues** 탭에서 **퀴즈 문항 순서를 실행마다 섞기**를 선택하고 `c`로 채팅에 추가합니다.
6. **아직 구현을 요청하지 않습니다.** 다음 레슨에서 계획부터 세웁니다.

> 워크트리는 별도 브랜치의 파일을 독립된 폴더에 둡니다. 그래서 첫 번째 세션의 미커밋 변경과 두 번째 작업이 섞이지 않습니다.
>
> `/worktree`가 `The queued prompt "/worktree" is waiting...` 상태로 멈추면 [TROUBLESHOOTING.md](../TROUBLESHOOTING.md#5-worktree가-queued-prompt-is-waiting-상태로-멈춤)를 참고합니다.
