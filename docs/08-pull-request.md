# 레슨 8 - CLI에서 생성, 검토, 병합

**워크트리 세션**의 변경 사항을 검토하고 풀 리퀘스트(PR)를 만든 뒤, 확인을 마치면 병합합니다.

**이 레슨에서 할 일**

- 변경 사항을 최종 검토합니다.
- 현재 브랜치에서 PR을 생성합니다.
- PR 내용과 동작을 확인합니다.
- `/pr agentmerge`로 병합합니다.

---

## 8-1. 변경 사항 최종 검토

```text
copilot> /diff
```

**문항 순서 섞기와 관련된 변경만** 있는지 확인합니다. 문제가 있으면 수정을 요청하고 다시 검토합니다. 확인이 끝나면 `Esc`로 닫습니다.

## 8-2. PR 생성

```text
copilot> /pr create
```

커밋·푸시·PR 생성 승인이 나오면 대상 파일과 브랜치를 확인한 뒤 허용합니다.

> 생성된 **PR 번호를 기록합니다.** PR 번호와 이슈 번호는 다를 수 있습니다. 이하 `N`은 실제 PR 번호로 바꿉니다.

## 8-3. PR 내용 확인

1. 사이드 패널 **Pull requests** 탭에서 생성된 PR을 선택합니다.
2. 제목, 설명, 변경 파일, 추가·삭제된 코드가 작업 내용과 맞는지 확인합니다.
3. 화면 아래 안내에 따라 `o` 키로 GitHub PR 페이지를 엽니다.
4. 병합 대상이 `main`인지 확인하고, **Files changed**와 **Checks**를 살펴봅니다. 검사가 설정되지 않은 저장소라면 검사 결과가 없을 수 있습니다.

PR 설명에 이슈 연결 문구가 없다면 요청합니다.

```text
PR #N의 설명에 Closes #2를 추가해 주세요. 기존 설명은 유지해 주세요.
```

> `Closes #2`는 PR이 기본 브랜치에 병합될 때 이슈 #2를 자동으로 닫습니다.

## 8-4. 브라우저에서 동작 확인

**현재 워크트리 세션**에서 실행합니다.

| OS | 명령 |
| --- | --- |
| Windows | `!Start-Process .\index.html` |
| macOS | `!open index.html` |
| Linux | `!xdg-open index.html` |

- [ ] 시작·다시 시작할 때 문항 순서가 바뀐다.
- [ ] 10문항이 중복·누락 없이 나온다.
- [ ] 정답 판정, 점수, 진행률이 정상이다.
- [ ] 키보드로 조작할 수 있다.

확인한 내용만 PR 댓글로 남깁니다.

```text
PR #N에 댓글을 남겨 주세요: “브라우저에서 시작·다시 시작 시 문항 순서 변경, 10문항의 중복·누락 여부, 정답 판정, 점수, 진행률, 키보드 조작을 확인했습니다.”
```

## 8-5. PR 병합

```text
copilot> /pr agentmerge
```

에이전트가 검사 결과와 피드백을 확인하고 필요한 조치를 진행합니다. 승인 요청은 내용을 확인한 뒤 허용합니다.

완료 메시지에서 **PR이 `Merged` 상태인지, 이슈 #2가 닫혔는지** 확인합니다.

---

## 체크포인트

- [ ] PR이 `main`에 병합됐다.
- [ ] 이슈 #2가 닫혔다.
