# 레슨 2 - 프로젝트 지침 작성

완성한 퀴즈를 바탕으로 프로젝트 구조와 작업 규칙을 담은 지침을 생성합니다. 이후 세션에서 Copilot이 이 지침을 참고하므로, 같은 안내를 프롬프트마다 반복할 필요가 줄어듭니다.

**이 레슨에서 할 일**

- `/init`으로 프로젝트 지침을 생성합니다.
- 생성된 내용을 검토합니다.
- 프로젝트에 맞게 규칙을 보완합니다.

> 이 레슨의 명령은 별도 안내가 없으면 **Copilot CLI 입력창**에 입력합니다. 터미널에서 실행하는 명령은 "터미널에서"라고 표시합니다.

---

## 2-1. `/init`으로 지침 생성

`/init` 뒤에 요청을 함께 입력합니다. 명령만 입력하면 `Command input required`가 표시될 수 있습니다.

```text
/init 이 프로젝트에 맞는 간결한 작업 규칙을 작성해 주세요.
```

지침은 `.github/copilot-instructions.md` 파일로 생성됩니다.

## 2-2. 생성된 지침 검토

```text
생성한 프로젝트 지침 내용을 수정 없이 보여 주세요.
```

지침이 영어로 작성됐다면 다음을 요청합니다.

```text
지침을 한글로 변환 적용하고 다시 내용을 보여주세요.
```

아래 항목이 포함됐는지 확인합니다.

- 앱 전체가 `index.html` 하나에 있고 빌드·서버·외부 의존성이 없다.
- 화면 흐름(시작 → 퀴즈 → 결과)과 주요 함수 역할
- 접근성(키보드 조작, 포커스), 라이트/다크 테마, `prefers-reduced-motion`
- 실행 방법: 브라우저에서 `index.html`을 직접 연다.

## 2-3. 규칙 보완

빠진 검증 규칙을 추가합니다.

```text
프로젝트 지침에 “코드 변경 후 브라우저에서 퀴즈 시작, 답 선택, 다음 문항 이동, 결과 화면, 다시 시작, 키보드 조작을 확인한다”는 규칙을 추가해 주세요. 이미 있다면 중복으로 추가하지 말고, 나머지 지침과 퀴즈 코드는 변경하지 마세요.
```

> **실행 순서가 중요합니다.** `/init`은 현재 코드를 분석해 지침을 만듭니다. 퀴즈를 만든 **뒤에** 실행해야 실제 구현에 맞는 지침이 나옵니다.

지침에는 코딩 스타일, 명명 규칙, 쓰지 않을 라이브러리, 주석 기준 등 반복해서 요청하던 사항을 함께 적어 둘 수 있습니다.
